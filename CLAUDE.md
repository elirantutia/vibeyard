# Vibeyard contributor guide

Vibeyard is an Electron desktop IDE for six CLI backends: Claude Code, Codex CLI, GitHub Copilot, Gemini CLI, Pi, and Oh my Pi. Source builds use Node 24 (`.nvmrc`). The published npm launcher accepts Node 18+ and downloads a packaged app.

## Build and checks

```bash
npm install
npm run build
npm test
npx tsc -p tsconfig.renderer.json --noEmit
git diff --check
```

`npm start` builds before launching. There is no hot reload. `tsconfig.test.json` is not a supported gate yet: its legacy target and test mocks produce type errors; see [audit status](docs/AUDIT_STATUS.md).

## Current contracts

- [Provider contracts](docs/provider-contracts.md) — registry, profiles, spawn arguments, transcripts and status sources.
- [Session lifecycle](docs/session-lifecycle.md) — PTY exit, title adoption, Kanban sync, persistence and watchers.
- [Security boundaries](docs/security-boundaries.md) — renderer/main boundary, paths, sharing and browser data.
- [Performance and resource limits](docs/performance.md) — search cancellation/cache storage, preview paging, event retention and remaining measurements.
- [UI conventions](docs/ui-conventions.md) — components, widgets, i18n and project layout.
- [Claude hook compatibility](HOOKS.md) — version-specific event payloads and status mapping.

Use `src/main/platform.ts` for OS checks and platform path helpers. Build path expectations with `path.join` or `path.resolve` in tests, including on Windows.

After implementation, review changed code for correctness and unnecessary complexity, run the relevant tests, and update the linked contracts. `/code-review` and `/simplify` have no definitions in this repository; perform those checks directly when the commands are unavailable. Do not commit, push or create a PR unless requested. `CHANGELOG.md` is generated by the release workflow.
