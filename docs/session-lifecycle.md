# Session lifecycle

Terminal keyboard input tracks the CLI's DEC private mode 9001 requests. While Win32 input mode is enabled, cursor/navigation keys are sent as Windows key records, preserving modifiers; this avoids ConPTY turning OMP arrow sequences into literal prompt characters. When disabled, xterm handles the keys normally. `win32-terminal-keys.ts` owns this adapter. Select-only settings dialogs take keyboard focus from the terminal when opened.

Hook inspector event ingestion is incremental: each turn reads at most 64 KiB, preserves partial JSONL records and UTF-8 bytes, and schedules further backlog reads. Individual records over 64 KiB are skipped. Renderer retention is bounded by both 2,000 events and 2 Mi characters per session. Closing a session cancels pending ingestion continuations and releases its reader state.

Pi/OMP launches use exclusive session directories, and discovery shares registration generations per watched directory rather than duplicating complete filename snapshots for each session. Registration still forces a fresh synchronous listing. During polling, directory listings are reused while mtimes are unchanged; rename events invalidate them, and a 30-second reconciliation refreshes them even after missed notifications. Two-second polling still checks for changes. Existing-file exclusion remains in force.

The renderer owns session records in `src/renderer/state.ts`; the main process owns PTYs. A non-shell CLI PTY exit destroys and removes its live session. `src/main/ipc-handlers.ts` owns replacement cleanup. The UI distinguishes active sessions, archived resumable sessions and history entries. State is saved to `~/.vibeyard/state.json` through an atomic temporary-file rename and flushed on quit.

Session activity changes on provider hook or transcript events. A completed event moves a linked Kanban task to Done. Closing or losing an unfinished session only clears its live `sessionId`; it does not complete the task. `board-session-sync.ts` resolves the owning project even while another project is selected.

An abnormal CLI exit is annotated: Pi/OMP can supply a fatal or signal reason through a trailing `session_exit` entry even when the process exits with code 0. The lookup checks the provider's transcript path if the watcher has not resolved one yet and ignores an exit marker older than the current launch. Otherwise the process exit code or signal supplies the reason. Crash history retains PID, code and signal, and offers Resume when a transcript exists. A user-initiated close removes the session before its PTY exit arrives, so it is not reported as a crash.

Numbered default names come from `src/renderer/state/session-naming.ts`. Live provider titles are adopted by `src/renderer/session-title.ts` when automatic titles are enabled and the user has not renamed the session. There is no main-process one-shot naming service or fifth-prompt title pass. A transcript-polled title (Pi/OMP) is only mirrored while a live PTY drives `session-transcript-sync`; a title generated or changed while Vibeyard was closed would otherwise be lost on re-open, so after state load the renderer sends every restored self-titling session to `session:syncRestored`, which re-registers title-only transcript sync (never status, to avoid reviving a stale status on a dead tab) and mirrors the title only for a session whose `cliSessionId` is already known. A session whose id was never persisted stays unresolved — ownership is not inferred from cwd + creation time, which can assign an unrelated conversation and persist it. A resumed session re-registers without the title-only flag and resumes full title/status mirroring; a restored tab closed without a resume releases its title-only entry via `session:release`.

`src/main/file-watcher.ts` watches file-tree and reader directories lazily, including the parent directory to survive atomic replacement. `src/main/git-watcher.ts` watches Git state separately, using recursive watching on Windows/macOS and capped per-directory watching on Linux. Hook `.events` reading advances its byte offset by bytes actually read, retains incomplete line bytes separately, and emits only complete parsed records. A size smaller than the offset resets the reader. See [performance and resource limits](performance.md) for exact bounds and oversized-record handling.
